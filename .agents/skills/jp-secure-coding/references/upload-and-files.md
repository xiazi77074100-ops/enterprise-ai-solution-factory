# アップロード・保存・ダウンロード・文書の解析

## 受け付け

1. 認証・認可（その案件のメンバー）を先に確かめる。
2. サイズ：リバースプロキシとアプリの両方で上限（既定 10 MB）。上限を超えたら読み込みを打ち切る（全部読んでから比べない）。
3. 形式：**拡張子・Content-Type・先頭バイト（マジックナンバー）の 3 つが許可リストで一致**するものだけ。
   | 形式 | 先頭バイト |
   |---|---|
   | PDF | `%PDF-` |
   | PNG | `89 50 4E 47 0D 0A 1A 0A` |
   | JPEG | `FF D8 FF` |
   クライアントが送る Content-Type は信用しない（照合に使うだけ）。
4. ページ数・画像の画素数に上限（PDF 30 ページ、画像は Pillow の `Image.MAX_IMAGE_PIXELS` を明示的に設定）。展開爆弾・PDF 爆弾を想定する。
5. 暗号化 PDF・JavaScript を含む PDF・添付ファイル付き PDF は受け付けない、または解析せずに「対象外」で止める（方針は ADR-003）。

## 保存

- 保存名は `uuid4()`。元のファイル名は DB に**表示用の文字列としてだけ**持つ（NFC 正規化、制御文字除去、255 文字以内）。
- 保存先は Web から配信しないディレクトリ（Docker のボリューム）。パーミッションはアプリのユーザーだけ。
- SHA-256 を計算して DB に保存する（証跡の `text_hash`・データセットの manifest と照合する）。
- 読み出しは「文書 ID → DB の保存パス → `Path.resolve()` が保存ルートの配下か確認」の順。利用者の文字列でパスを作らない。
- 保持期限と削除手順を決める（ADR-004）。削除は DB と実ファイルの両方、削除したことを監査ログに残す。

## ダウンロード・エクスポート

- 認可付きの API で返す。`Content-Disposition: attachment; filename*=UTF-8''<RFC 5987 で符号化した名前>`、`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`。
- 元の文書をブラウザ内で表示する場合も `Content-Type` はサーバが決めた値（`application/pdf` など）。HTML・SVG として返さない。
- **CSV エクスポートは CSV インジェクション対策**：セルの先頭が `=` `+` `-` `@` タブ・CR のときは先頭に `'` を付ける。文字コードは Excel で開く前提なら UTF-8 BOM 付き（方針は設計書に明記）。

## 解析（DocumentParser）

- 解析は別プロセス（ワーカー）で行い、時間（例 60 秒）・メモリの上限を付ける。失敗・時間切れは `failed` で、成功にしない。
- 解析ライブラリは保守されていて、ライセンスが許すもの（AGPL のものは採用前に ADR で判断）。版を固定し、脆弱性を CI で検査する。
- XML を含む形式（DOCX など）を扱うなら `defusedxml` を使い、外部実体（XXE）を解決しない。POC では PDF と画像だけを推奨。
- 抽出したテキストは **信用しないデータ**。そのまま LLM の指示部分に入れない（`ai-llm-mcp.md`）。
