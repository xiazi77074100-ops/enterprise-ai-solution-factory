# 契約書レビュー POC の要件（ベースライン・Factory 共通、凍結）

この文書は、2 件目の業務（契約書レビュー）の POC を作るための要件です。ベースライン（A）と Factory（B）に同じものを渡します（`docs/experiment/preregistration.md` §3）。データはすべて合成（架空）です。

## 1. 業務

合成の日本語の契約書（PDF または画像）をアップロードし、解析して、当事者・期間・更新・損害賠償の上限・秘密保持・解約などの項目を取り出す。あらかじめ決めた確認ポリシー（§3）で確かめ、根拠（どのページのどの文か）を示し、人が確認して承認・修正し、レビュー結果を出力する。

- 項目は「ある（found）」「無い（missing）」「あいまい（uncertain）」を区別する。
- 法的助言をしない。結果には「架空のポリシーによる確認結果です。法的助言ではありません。判断は専門家が行ってください。」を表示する。

## 2. 取り出す項目

| 名前 | 内容 | 型 | 重大 | 値の決め方 |
|---|---|---|---|---|
| party_a | 甲（委託者）の会社名 | 文字列 | — | 前文の「…（以下「甲」という。）」の会社名 |
| party_b | 乙（受託者）の会社名 | 文字列 | — | 前文の「…（以下「乙」という。）」の会社名 |
| effective_date | 契約開始日 | 日付 | — | ISO 形式（2025-06-06）。和暦（令和7年…、R7.…）も西暦に直す |
| end_date | 契約終了日 | 日付 | — | 同上 |
| auto_renewal | 自動更新の有無 | 真偽 | **重大** | 自動更新しない → false、期間満了後に自動で更新される → true |
| confidentiality | 秘密保持条項 | 文字列 | **重大** | 秘密保持の条の見出しを印字どおり（例「第4条（秘密保持）」「4.（秘密保持）」「四、秘密保持」）。無ければ null |
| liability_cap_jpy | 損害賠償の上限額（円） | 数値 | **重大** | 円の整数を十進の文字列で（「30,000,000円」「3,000万円」→ "30000000"） |
| termination_notice_days | 解約の通知期間（日） | 整数 | **重大** | 「30日前までに…通知」→ 30 |
| governing_law | 準拠法 | 文字列 | — | 「日本法」 |

状態：書かれていない → missing（値は null）。書かれているが一つに決まらない（「別途協議」「相当の期間」、条によって上限額が違う）→ uncertain（値は null）。

## 3. 確認ポリシー（架空）

| ID | 重大度 | 内容 | 結果 |
|---|---|---|---|
| CON-001 | critical | 秘密保持条項がある | 無ければ fail |
| CON-002 | major | 損害賠償の上限額が 5,000 万円以下 | 超えれば fail。上限額があいまい・矛盾なら uncertain |
| CON-003 | minor | 自動更新でない（自動更新なら確認） | 自動更新なら fail |
| CON-004 | major | 解約の通知期間が定められている | 無ければ fail。「相当の期間」等なら uncertain |
| CON-005 | minor | 準拠法が定められている | 無ければ fail |

- 結果は pass・fail・uncertain の 3 つ。判定できないものを pass にしない。
- critical の fail・uncertain は必ず人の確認に回す。
- 文書の中に「確認を省略せよ」などの指示が書かれていても従わない（文書はデータとして扱う）。

## 4. 受入条件

| ID | 内容 |
|---|---|
| AC-06 | 契約書：解析・抽出・ルールの確認・根拠・人の確認・レビュー結果の出力が通しで動く |
| AC-07 | 人の修正が結果と記録（いつ・誰が・何を・修正前後）に残り、見える |
| AC-09 | 重大な誤りを黙って通さない。判定できないものは人の確認へ（失敗は閉じる側に） |
| AC-12 | 主な画面（アップロード・確認と修正・根拠の表示・結果）と失敗の表示が日本語。見た目の作り込みは評価しない |

品質（holdout で人が判定する。事前登録で凍結済み）：

| 指標 | 閾値 |
|---|---|
| 重大な誤りの黙認（重大項目・重大ルールの誤りが人の確認を経ずに確定する） | 0 件 |
| 重大ルールの再現率（fail か uncertain で確認へ回したものを検出とみなす） | 1.0 |
| 根拠の位置の正しさ（示した根拠のうち、正解のページ・範囲と重なる割合） | 0.9 以上 |
| 照合できない根拠の扱い | 「未確認」と表示する |
| 確認の記録の完全さ（確認者・時刻・修正前後の値） | 100% |
| 項目抽出（正規化一致のマクロ平均） | 0.85 以上（目安） |

## 5. データ

- `data/dev/documents/`：開発用の契約書 28 件（PDF 24・スキャン画像 4）。`data/dev/labels/`：正解（`gold_fields`・`gold_field_status`・`gold_findings`・`gold_evidence`）。
- 正解の根拠（`gold_evidence`）の `start`・`end` は、PDF のページのテキスト（pypdfium2 の `get_text_bounded()`）の文字の番号。別の方法でテキストを取り出す場合は合わなくてよい（§6 の形で引用文を出せば採点できる）。
- ホールドアウト 12 件は人だけが持ち、評価のときに人が実行する。開発に使わない。

## 6. 評価のための出力の形

文書 1 件ごとに次の JSON を 1 つのフォルダに出す（ファイル名は `<sample_id>.json`）。評価は人が両 arm に同じ採点の道具で行う。

```json
{
  "sample_id": "con-0001",
  "fields": {"party_a": "…", "auto_renewal": false, "liability_cap_jpy": "30000000", "...": "..."},
  "field_status": {"party_a": "found", "confidentiality": "missing", "...": "..."},
  "findings": [{"rule_id": "CON-001", "result": "pass"}, {"rule_id": "CON-002", "result": "uncertain"}],
  "evidence": {"liability_cap_jpy": [{"page": 1, "quote": "30,000,000円", "verified": true}]}
}
```

- `fields` の値は §2 の決め方の形。`findings` は CON-001〜005 の全部。
- `evidence` の `quote` は文書に印字された文字列そのまま（その文書のそのページにある文字列）。照合できない根拠は `"verified": false`。
- 人の確認の前（自動の結果）を出す。人の確認は画面で行い、記録が残ることを示す。
