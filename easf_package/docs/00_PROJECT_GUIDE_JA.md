# 00 — プロジェクト概要・開発運用ガイド（日本語）

## 1. プロジェクト名

**Enterprise AI Solution Factory（EASF）**  
推奨リポジトリ: `enterprise-ai-solution-factory`

## 2. 目的

日本企業・企業グループの AI コンサルティング、プリセールス、設計・開発チームが、業務要件から検証可能な POC を短期間で構築し、実行結果・品質・再利用実績を資産として蓄積できる仕組みを検証する。

本製品は SES 企業向けの販売 SaaS でも、Claude Code / Codex の単なる UI でも、企業グループ全体の AI 基盤を置き換える製品でもない。

## 3. POC の対象

### A. 請求書処理

合成請求書のアップロード → 文書解析 → 項目抽出 → 業務ルール確認 → 人手による確認・修正 → 構造化データ出力。実際の振込や会計計上は行わない。

### B. 契約書レビュー

合成契約書のアップロード → 条項抽出 → 事前定義ルールによる確認 → 根拠箇所の表示 → 人手による確認・修正 → レビューレポート出力。法的助言として提供しない。

### 共通能力

DocumentParser / StructuredExtractor / RuleValidator / EvidenceLocator / HumanReview / ResultExporter を候補とする。単なるコードの複製ではなく、同一のバージョン管理済み Capability を異なる設定で実行し、証跡を残す。

## 4. 技術方針

- フロントエンド候補: React / TypeScript / Vite / Ant Design
- バックエンド候補: Python / FastAPI
- メタデータ管理候補: PostgreSQL
- 構成: モジュラーモノリス、Docker Compose
- 接続: MCP Tool / REST / Local / LLM を抽象化する Adapter
- 技術選定は確定ではない。Phase 0 の ADR とレビューで決定する。

## 5. 受入条件

1. 二つの業務 POC が実際に動作し、人手による確認を含む業務フローが完結する。
2. Capability Catalog、バージョン固定、Schema 検証、構成、実行、トレース、評価、再利用実績が実動する。
3. 各業務で30〜50件程度の合成テスト例を用意し、独立したホールドアウトデータを確保する。
4. 重要な誤判定を黙って通過させず、不確実な場合は人手による確認へ回す。
5. Claude Code / Codex を使った通常の AI Coding と公平に比較し、総工数30%以上の削減を**目標として検証**する。未達の場合も結果を正確に報告する。
6. 実際の工数、API 費用、修正・統合作業、品質を記録する。
7. 二つの文書系業務だけで、あらゆる業種への一般化を主張しない。

## 6. AI Coding の役割分担

**Claude Code（統合責任者）**: Phase 0 の設計、共通契約、バックエンド中核、統合、ゲート報告。  
**Codex（独立レビュー・並行担当）**: 設計レビュー、独立テスト、許可された UI・業務ルール実装、比較実験。  
**人間（プロジェクト責任者）**: 仕様・ADR・費用・フェーズ移行の承認。

同一ファイルの並行変更は禁止する。共通 API、Schema、DB マイグレーションは担当を一本化する。

## 7. 段階計画

| フェーズ | 内容 | ゲート |
|---|---|---|
| Phase 0 | 設計、契約、実験方法の確定 | G0 |
| Phase 1 | プロジェクト管理、Catalog、基本 UI | G1a |
| Phase 2 | Workflow 実行、Trace、Human Review | G1b |
| Phase 3 | 請求書処理 POC | G2 |
| Phase 4 | 契約書レビュー POC、再利用実証 | G3 |
| Phase 5 | 品質・安全性・工数比較 | G4 / G5 |
| Phase 6 | 日本語デモ、成果報告、独立監査 | 最終承認 |

**ゲート承認前に次フェーズへ進まない。**

## 8. 言語方針

業務画面、メッセージ、デモ、進捗・レビュー報告は日本語。API、クラス名、JSON キー、英語で書かれた既存の技術資料・Prompt は英語のままでよい。新規の中国語文言を作らない。

## 9. セキュリティ・権利関係

合成データまたは権利・使用許可を確認したデータだけを扱う。勤務先や顧客の非公開コード、情報、アカウント、端末、勤務時間を無断で利用しない。外部への発表前に権利関係と公開範囲を確認する。実在する SBI / MCT の未公開 API や接続仕様を推測で実装しない。

## 10. 最初の作業指示

Claude Code に `prompts/00_ORCHESTRATOR_CC.md` を渡し、**Phase 0 の計画だけ**を作成させる。Codex には `prompts/01_CODEX_PARALLEL.md` を渡して独立レビューを依頼する。人間が G0 を承認するまではアプリケーションコードを書かない。
