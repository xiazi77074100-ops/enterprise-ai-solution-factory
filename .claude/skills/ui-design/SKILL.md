# ui-design — EASF の画面の決まり

sales-assistant の `ui-design`（2026-10-14 版）の規約を EASF 向けに書き直したもの。部品の名前・振る舞いの決まりを引き継ぎ、sales-assistant 固有の画面・業務用語・配色・データは含めない。
汎用の原則は `japan-enterprise-frontend`、画面の一覧と流れは `easf_package/docs/05_UI_AND_DEMO.md`、画面の安全は `jp-secure-coding`（frontend-react.md）。

前提（ADR-009）：React ＋ TypeScript ＋ Vite ＋ Tailwind CSS ＋ Radix（ヘッドレス）。共通部品は Phase 1 で `frontend/src/components/` に作り、**画面ごとに自作しない**。迷ったら既存の画面を真似る（見本の画面は Phase 1 で決めてここに書く）。

## 1. 画面の骨組み

```tsx
<div className="flex min-h-0 flex-1 flex-col gap-3 p-4">
  <PageHeader title="能力カタログ" actions={<Button>…</Button>}>
    <span>更新日の新しい順</span>             {/* 説明の行。件数はページ送り欄に出す */}
  </PageHeader>
  …
</div>
```

- **ページ見出しは `PageHeader`**。画面名はサイドバーの現在地で分かるので h1 は `sr-only`。見えるのは 1 行：左に説明 12px、右端に操作ボタン。
  - 見出しが記録の名前のとき（案件詳細の案件名、実行詳細の実行番号）だけ `titleVisible` で 18px の見出しを出す。
  - 詳細から一覧へ戻る導線は `breadcrumb`（12px・灰色の `一覧名 › 記録番号`、一覧名は押せる）。枠付きの「戻る」ボタンを作らない。
- 見出し・主要操作を上部に残したい画面（詳細・確認・長い入力）は、浮かせず固定する：外枠 `flex min-h-0 flex-1 flex-col`、見出し帯 `shrink-0 border-b`、本文 `min-h-0 flex-1 overflow-auto`。sticky・影・ぼかしを使わない。
- **一覧の上の条件の行は `FilterBar`**（検索・絞り込み・右端に操作）。`flex flex-wrap` で自作しない。条件の行に件数を出さない。
- データを変えた結果は共通の `ActionDialog`（§5.4）。読み込み中・業務上の注意だけをページ内の `role="status"` にする。

## 2. 数字のタイル

**必ず `StatTile`**：上に見出し帯、数字は中央、**単位は右下**（数字に含めない）、補足は左下、上端に 2px のアクセント線。

| 決まり | 内容 |
|---|---|
| 単位 | `unit` に渡す。金額は `yenParts(n)` で数と単位（円・万円）に分ける |
| 大きさ | `lg` 28px／`md` 24px／`sm` 18px（日時など長い値） |
| 状態 | `tone`（critical / serious / warning / good）。critical で 1 以上なら「要対応」の面 |
| 数値の出所 | **測った値・記録から数えた値だけ**。目標値・見込みを実績のタイルに出さない。評価の数値はデータセットの版と一緒に出す |

## 3. パネル

見出し帯は 40px・15px 太字（700）・幅いっぱいの区切り線。`<Panel title icon meta actions>` を使う。複数のパネルを束ねる見出しは `section-title`（14px）。パネルの中の小見出し・項目名は 12〜13px。

## 4. 表・一覧

- 表はカードの中で横スクロール（`overflow-x-auto`）、`table` に `min-w-[…px]`。**ページ全体を横スクロールさせない**。
- 行は淡いゼブラ（共通の CSS で。画面ごとに `i % 2` を書かない）。ホバー・選択・状態色が優先。
- 見出し行は 12px・`muted`・**折り返さない**（文言は 2〜6 文字目安）。`th scope="col"`。
- 数字は右寄せ＋`tabular-nums`。状態は `Badge`（`tone`、折り返さない）。
- 列が多い表は「誰の行か」が分かる列（案件名・実行番号）を左に固定し、ID・版は名前の下に 11px。
- 0 件は表の中に「条件に一致する…はありません」を中央寄せ。

### 4.1 長い文字は「…」で切り、ホバーで全文

案件名・要件・Capability 名・ファイル名・ルールの説明・確認のコメントなど、長くなりうる文字は `Truncate` で包む（文字は DOM に全部残る）。表では **中の要素に `max-w-[…px]`**（`td` に付けても効かない）。文章は `lines={2}`。日付・金額・件数・状態・版番号は切らずに `whitespace-nowrap`。ボタン・見出し・エラー・詳細の本文は切らない。

### 4.2 ページング

件数が増える一覧（案件・実行・確認タスク・評価・トレース・監査ログ）には `usePagination` ＋ `Pagination` をカードの最下部に。表示は `1,234 件中 51–100 件目を表示`、件数切替 25/50/100/200（既定 50）。サーバ側のページングと上限（`jp-secure-coding` backend §9）に合わせる。自前でページ番号・「もっと見る」を作らない。

## 5. フォーム・ダイアログ

### 5.1 入力フォームの 3 つの約束

1. **正しく入力するまで主ボタンを押せない**（`disabled={!form.valid}`）。押してからエラーを出さない。
2. **必須は項目名の後ろに赤い `*`**。「（必須）」と書かない。条件つきの必須は条件を満たしたときだけ。
3. **不正な入力は欄の下に赤字、入力欄の枠と項目名を赤**（`aria-invalid`）。

部品は `Field` ＋ `useFormCheck`、チェック関数は `required` `maxLength` `numberRange` `pattern` `firstError`。エラーは入力のある項目はすぐ、空の必須は欄を離れたとき。開いた直後から赤くしない。
文言：`{項目}を入力してください。`／`{項目}を選択してください。`／`{項目}は{n}文字以内で入力してください。`／`{項目}の形式が正しくありません（例：…）。`。何が悪くてどう直すかを書く。
**サーバのチェックが正**：画面のチェックは同じ条件と文言でそろえるが、サーバ側（Pydantic・業務ルール）を消さない。サーバの 422 は該当欄のエラーに出す。

### 5.2 選択肢

| 場面 | 部品 |
|---|---|
| 一覧の絞り込み（件数・種類を問わず） | `MultiSelect`（複数選択＋検索。未選択＝すべて）。最後に `ClearFilters`（「条件をクリア」） |
| フォームの単一選択で、選択肢がデータ由来か 8 件超（案件・Capability・版・確認者） | `SearchSelect` |
| 少数の固定区分（〜7 件） | `Select` |

### 5.3 ダイアログ・確認・ボタン

- ダイアログは `Modal`（Esc・フォーカス管理。背景をぼかさない）。フッタは左に補足（`FormStatus`＝押せない理由）、右に「取消」→ 主ボタン。
- 削除・取下げ・**承認・却下・版の公開・実行の開始**など戻せない／重い操作は `ConfirmDialog` で対象名と結果を見せてから。`window.confirm` を使わない。
- ボタンは主操作 1 つだけ `default`、他は `outline` / `ghost`。業務操作は「小さいアイコン＋動詞」（「承認」「修正して承認」「差し戻し」「実行」）。アイコンだけのボタンは閉じる・ページ送りなどに限り、`aria-label` と 32px 以上の押下領域。
- 色は意味で固定：主操作は主色、成功の結果だけ緑、一覧の行ごとの削除は普段は無彩色（ホバーで赤）、最後の不可逆の確定だけ赤い面。

### 5.4 待ち・通知

- **すべての API の書き込みは共通の `useApi()` を通す**：押したボタンに `loading`（二重送信を防ぐ）、画面上端に線、`Modal` は処理中を覆う。
- 画面の読み込みは骨組み（skeleton）→ フェードイン。一覧の絞り込み・ページ送りは表を薄くして線。
- 結果は `ActionDialog`（画面中央の非モーダル）：成功は 4 秒で自動で閉じる・「元に戻す」を付けられる、失敗は閉じない・`role="alert"`。エラーにはサーバの `message` と `trace_id` を出す（スタックは出さない）。
- 長い処理（Workflow の実行）は待たせ続けず、実行モニターで状態を表示する。

## 6. 文字・色

| 用途 | サイズ | 字重 |
|---|---|---|
| ページ見出し（記録名の画面だけ） | 18px | 800 |
| パネル見出し | 15px | 700 |
| まとまりの見出し・タイルの見出し | 14px | 700 |
| 本文・表 | 13px | 400（強調 600） |
| 説明・補足・表の見出し | 12px | 400 |
| 注記・根拠・日時・ID | 11px（**下限**） | 400 |

- 6 段以外の大きさを足さない（タイルの数字だけ 28/24/18px）。階層は大きさと字重で作り、補助文字をさらに薄くしない。
- 色はトークン（`bg-card` `text-foreground` `text-muted-foreground` `border-border` …）だけ。16 進数を直書きしない。**状態の文字は ink 系**（`text-success-ink` など。面・線・アイコン用の色を白地の文字に使わない）。状態は色だけでなくアイコン＋文言でも示す。
- 配色は EASF で決める（Phase 1 の `theme.css`）：落ち着いた中間色、主色は 1 色、影は 1 段・弱く、グラデーション・地紋・カーソル追従の光などの装飾を使わない。ダークモードはトークンの差し替えだけで効くように書く。
- 動きは読み込みの骨組み・API の線・フェードインだけ。`prefers-reduced-motion` で止める。

## 7. EASF 固有の表示

| 対象 | 決まり |
|---|---|
| 実接続と模擬 | 実行・ノード・アダプタに常にバッジ：「実行」／「模擬（MOCK）」。模擬は色だけでなく文言で。API の `execution_mode` から出し、画面で決めない |
| 合成データ | 文書・データセットに「合成データ」のバッジ。画面の隅に「検証用（本番利用不可）」 |
| AI の出力 | 「AI 下書き」のバッジ。人の確認前の値と確認後の値を並べ、修正した項目は修正前の値も見せる |
| 根拠（evidence） | 文書の該当ページ・範囲を本文の横に並べて表示（`<mark>` を React ノードで）。照合できない根拠は「未確認」と明示し、作らない |
| ルールの判定 | 「該当あり（fail）・該当なし（pass）・不明（uncertain）」の 3 値。`rule_id` と重大度を必ず出す。契約は「法的助言ではありません」の注記 |
| 版 | `document.parser@1.0.0` の形を等幅 11px で。固定された版であることが分かるように |
| 状態の遷移 | 実行・確認タスクの状態は `Badge` と手順の表示で。確認待ちの実行を「完了」に見せない |

## 8. 文言

- 画面の文字は日本語。英略語を画面に出さない（DAG →「処理の流れ」、Capability →「能力」など。対応表は Phase 1 で用語集 `docs/design/glossary.md` に）。技術識別子（`capability_id`・版）は表示してよい。
- 件数は「n 件」、人は「n 人」。日付は `YYYY-MM-DD`、日時は `YYYY-MM-DD HH:mm`（JST）、期間は `YYYY-MM-DD〜YYYY-MM-DD`。金額は明細 `¥1,234,567`、集計は万円。
- 中国語の語を使わない。「開通」ではなく「有効」。

## 9. 作ったら確かめる

1. `npm run build`、画面を **1440px と 390px** で開く（ページの横スクロールなし、見出し・単位が崩れない）。Playwright で操作し、コンソールエラーがないこと。
2. 一覧を足したら長い文字のテスト（見出しが折り返さない・列が伸びない・吹き出しが出る）に追加。
3. 画面・操作・入力チェック・権限を変えたら `spec-sync` で設計書を同じコミットで直す。

## やってはいけない

| ✗ | ○ |
|---|---|
| 画面ごとに h1 を大きく出す | `PageHeader`（記録名の画面だけ `titleVisible`） |
| 数字と単位を 1 つの文字列でタイルに | `unit` に分ける |
| 手作りの数字カード | `StatTile` |
| 状態色を白地の文字に | ink 系 |
| 10px 以下の文字 | 11px 以上 |
| 主ボタンをいつでも押せて押してからエラー | `disabled={!form.valid}` と欄ごとのエラー |
| 一覧の絞り込みに `<select>`＋「すべて」 | `MultiSelect` |
| `td` に `truncate` | 中の要素に `Truncate`＋`max-w` |
| 模擬の結果を実行と同じ見た目で | 「模擬（MOCK）」バッジ |
| 根拠が見つからないのに位置を表示 | 「未確認」 |
| `dangerouslySetInnerHTML` でハイライト | 文字列を分割して React ノード |
