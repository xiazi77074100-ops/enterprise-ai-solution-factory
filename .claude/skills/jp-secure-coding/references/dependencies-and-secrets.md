# 依存関係・ライセンス・秘密情報・コンテナ

## 依存関係

- 追加する前に確かめる：保守されているか（最終リリース・Issue の対応）、ライセンス、既知の脆弱性、日本語文書への対応、代わりに標準ライブラリで足りないか（`ponytail`）。結果を ADR か `DECISIONS.md` に 1 行残す。
- ロックファイルを固定する（Python は `uv.lock` などツールは ADR、Node は `package-lock.json`）。CI ではロックどおりに入れる（`npm ci`）。
- CI で既知の脆弱性を検査する：`pip-audit`、`npm audit --omit=dev`、`osv-scanner`。**高・重大が残ったらゲートを通さない**（受容するなら理由と期限を `DECISIONS.md` に）。
- ライセンス：MIT / BSD / Apache-2.0 / ISC / PSF を基本とする。**GPL / AGPL / SSPL・商用制限付きは採用前に ADR で判断**（例：PyMuPDF は AGPL か商用、MinIO は AGPL）。外部から取り込んだ skill・コードは LICENSE と出所（URL・コミット・取得日）を残す。
- 可能なら SBOM（CycloneDX）を出力し、ゲートの証跡に入れる。

## 秘密情報

- 秘密は環境変数で渡し、設定クラス（`pydantic-settings`）で読む。`.env` はコミットしない（`.gitignore`）。見本は `.env.example`（値は空か `CHANGE_ME`）。
- コード・テスト・フィクスチャ・ドキュメント・コミットメッセージに実在のキー・パスワード・トークンを書かない。テスト用の値は明らかに偽物と分かるもの。
- `gitleaks` を pre-commit と CI で実行する。漏れたら履歴から消すだけでなく **キーを失効させる**。
- 秘密を `repr` / ログ / 例外メッセージに出さない（`SecretStr` を使う）。
- 開発用の初期管理者パスワードを固定値にしない（初回起動時に生成して表示、または環境変数で必須）。

## コンテナ・実行環境

- ベースイメージは版を固定（ダイジェスト推奨）、slim 系。root で実行しない（`USER`）。
- DB・内部サービスのポートをホストの外へ公開しない（`127.0.0.1:` にバインド）。DB の既定パスワードを使わない。
- `trivy image` / `trivy config` で検査する。
- デバッグ用の設定（`--reload`、`DEBUG=True`、詳細なエラー）は開発環境だけ。診断を受ける環境は本番相当の設定にする。
