# 書式

## ADR

```markdown
# ADR-NNN <題名>

| 項目 | 内容 |
|---|---|
| 状態 | 提案 / 承認 / 却下 / 置き換え（ADR-xxx） |
| 日付 | YYYY-MM-DD |
| 作成 | Claude Code / Codex / 人 |
| 承認 | （人間の名前・日付。承認前は空欄） |

## 状況
（何を決める必要があるか。制約：予算・期間・ライセンス・日本語文書・セキュリティ）

## 選択肢
| 観点 | 案 A | 案 B | 案 C |
|---|---|---|---|
| 保守状況（最終リリース・確認日） | | | |
| ライセンス | | | |
| セキュリティ（既知の脆弱性・攻撃面） | | | |
| 日本語文書への対応 | | | |
| 費用 | | | |
| 学習・実装の手間 | | | |

## 決定
## 理由
## 影響・やらないこと
## 確かめた資料（URL・確認日）
```

## テスト仕様書（試験項目表）

| 列 | 内容 |
|---|---|
| 試験 ID | `T-<モジュール>-NNN` |
| 受入条件 | `AC-xx`（`easf_package/docs/03`） |
| 観点 | 正常／異常／境界／権限／セキュリティ／性能 |
| 前提条件 | データ・ロール・状態 |
| 手順 | 番号付き |
| 期待結果 | 判定できる形（「正しく動く」は不可） |
| 自動化 | テストのパス（`tests/...::test_...`）／手動 |
| 結果 | OK / NG / 未実施（理由） |
| 実施日・実施者・コミット | |
| エビデンス | `reports/...` のパス |

## 試験成績（ゲートごとの集計）

```markdown
| 区分 | 項目数 | OK | NG | 未実施 | 実行コマンド | ログ |
|---|---|---|---|---|---|---|
| 単体 | | | | | `pytest tests/unit -q` | reports/... |
| 結合 | | | | | | |
| 契約 | | | | | | |
| セキュリティ | | | | | | |
| 画面（E2E） | | | | | | |
```
NG と未実施は 1 件ずつ理由と対応予定を書く。

## レビュー指摘票

| 列 | 内容 |
|---|---|
| 指摘 ID | `RV-<ゲート>-NNN` |
| 区分 | BLOCKER / MAJOR / MINOR / 質問 |
| 観点 | 仕様／設計／セキュリティ／テスト／規約／性能 |
| 場所 | ファイル:行、画面、API |
| 内容 | 何が問題か、再現手順 |
| 修正案 | |
| 対応 | 対応済み（コミット SHA）／対応しない（理由・承認者） |
| 確認者・確認日 | 指摘者が閉じる |
