# 脆弱性診断報告書の書式

`reports/security/<YYYY-MM-DD>/report.md` に、この形で書く。

```markdown
# 脆弱性診断報告書（自己診断）

| 項目 | 内容 |
|---|---|
| 対象 | EASF <コミット SHA>（ブランチ） |
| 環境 | ローカル Docker Compose、EASF_ENV=assessment、OS / ブラウザ |
| 期間 | YYYY-MM-DD HH:mm 〜 YYYY-MM-DD HH:mm（JST） |
| 実施者 | 人 / Claude Code / Codex（誰が何をしたか） |
| 基準 | IPA「安全なウェブサイトの作り方」（版）、ウェブ健康診断仕様（版）、OWASP ASVS（版・レベル）、OWASP Top 10 for LLM 2025 |
| 評価方法 | CVSS v3.1 基本値 → 高・中・低・情報 |
| 対象外 | 例：メール機能（機能なし）、TLS（ローカル環境） |

## 1. 総評
（2〜5 行。高・中の有無、主な傾向、ゲート判定）

## 2. 件数
| 重大度 | 件数 | 対応済み | 受容 | 未対応 |
|---|---|---|---|---|
| 高 | | | | |
| 中 | | | | |
| 低 | | | | |
| 情報 | | | | |

## 3. 実施した検査
| 段 | 道具（版） | コマンド | 結果ファイル | 結果 |
|---|---|---|---|---|
| SAST | ruff x.y / bandit x.y / semgrep x.y | … | sast/… | 検出 n 件（誤検知 m 件） |
| … | | | | 未実施（理由） |

## 4. 指摘一覧
| ID | 重大度 | CVSS | 項目 | 場所 | 状態 |
|---|---|---|---|---|---|
| VA-001 | 中 | 5.4 (AV:N/AC:L/…) | 認可制御の不備 | GET /api/v1/runs/{id}/trace | 対応済み（再診断 OK） |

## 5. 指摘の詳細（1 件ずつ）
### VA-001 認可制御の不備（中）
- 場所：
- 概要：
- 再現手順：（curl などそのまま実行できる形。秘密は伏せる）
- 影響：
- 原因：
- 対策：（根本的解決／保険的対策）
- 再発防止のテスト：`tests/security/test_xxx.py::test_yyy`
- 再診断：YYYY-MM-DD、コミット SHA、結果

## 6. 受容した指摘
| ID | 理由 | 代替策 | 期限 | 承認者・日付 |

## 7. 手動診断の結果
（checklist.md の全 ID と結果）

## 8. 制約・注意
（自己診断であり第三者診断の代わりではないこと、未実施の検査、環境の違い）
```
