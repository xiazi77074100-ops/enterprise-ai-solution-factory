| 正本のタスク | 現在の証拠 | 次に必要な作業 |

| P5-01 ベースライン | 別リポジトリ・別セッションで本体とCR-1を実施済み（D-042・D-046）。ホールドアウトの集計値は既存報告にある | 既存の人の時間・費用・環境差を整理。新たなベースライン実装は始めない |

## 4. 実験・安全の境界

- ホールドアウトは開かず、生成・再評価もしない。AIが読むのは既存の集計値だけ。再評価が必要なら人が新しい評価の手順とデータを別途判断する。
- `easf-baseline-contract` のコードを読まない。既存の証拠不足は不明として記載する。
- D-047の評価済みWorkflow・Rule pack・Capability実装と契約1.0.2を、この移行準備で変更しない。修正と評価の版を混同しない。
- 診断先はEASFのローカルassessment環境だけ。DBは専用の `_test` のみ、外部API・実LLM・実在顧客データ・送金・会計計上は対象外。
- 診断利用者は一意のIDで作成し、作成成功した対象だけを必ず後始末する。接続URI・Cookie・CSRF等の秘密は提出前に秘匿化して再検査する。
- 新しい有料サービス・公開・追加権限を今回の継続指示から推測で導入しない。契約や単独所有ファイルの変更はCCの手順に従う。

## 5. 受入条件・費用・止まる地点

G4は正本の独立評価・安全・再現可能な報告の条件で判定する。AC-04/07/08/09/12/13/14を証拠に結び付け、検査未実行・原因不明・来歴不足を成功として埋めない。セキュリティの高・中、SCAの高・重大、秘密情報の条件は既存の診断基準を維持する。

G5の比較・事業説明では、M1を測れていないことを明記し、成功・不成功の断定や損益分岐を捏造しない。事前登録の成功条件を後から変更しない。G4の承認、Phase 6と外部共有は人の判断を待つ。
