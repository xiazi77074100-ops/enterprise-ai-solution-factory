# 見積（Phase 0 時点）

**見積であり実績ではない。** 実績は `HUMAN_TIME_LOG.csv`・`COST_LEDGER.csv` に記録し、ゲートごとにこの表と比べる。人の時間は、AI への指示・レビュー・判断・テスト確認にかかる時間（AI の作業時間は含まない）。

| フェーズ | 主な作業 | 人の時間（見積） | 期間の目安 | 追加現金支出（見積） |
|---|---|---|---|---|
| Phase 0 残り | Codex レビュー（P0-02）・合成データ計画と事前登録（P0-04）の確認、指摘の反映、G0 判断 | 4〜6 時間 | 〜1 週 | 0 円 |
| Phase 1 | 雛形・DB・認証・Catalog・OpenAPI・UI の枠と共通部品・CI | 10〜14 時間 | 1.5 週 | 0 円 |
| Phase 2 | Composer・Executor・アダプタ（mock LLM・ローカル MCP）・トレース・確認の一時停止 | 10〜14 時間 | 1.5 週 | 0 円 |
| Phase 3 | 請求書：合成データ生成・6 Capability・評価 | 10〜14 時間 | 1.5 週 | 0 円（mock のまま）〜 実 LLM の場合は承認後 |
| Phase 4 | 契約書：Rule pack・設定・再利用の証拠・要件変更 | 6〜10 時間 | 1 週 | 同上 |
| Phase 5 | ホールドアウト評価・セキュリティ自己診断・ベースライン | 10〜16 時間 | 1.5 週 | 実 LLM を使うなら最大 5,000 円（D-008） |
| Phase 6 | デモ・報告・独立監査 | 4〜6 時間 | 0.5 週 | 0 円 |
| 合計 | | 54〜80 時間 | 約 8 週 | 0〜5,000 円 |

前提と注意：
- ADR-009 を B（Tailwind ＋ Radix）にすると、Phase 1 の UI の共通部品で人の時間が 2〜3 時間増える見込み。
- 実 LLM を使わない場合、抽出の品質は mock の固定応答になり、品質の評価は「エンジンとルールの評価」に限られる。実 LLM の要否は Phase 3 の前に判断する。
- 見積の根拠は作業の分解と過去の類似作業の感覚で、計測に基づくものではない。
