# ADR-008 ベースライン実験の実施順序

| 項目 | 内容 |
|---|---|
| 状態 | 承認（D-007） |
| 日付 | 2026-10-18 |
| 作成 | Claude Code |
| 承認 | プロジェクト責任者 2026-10-18 |

## 状況
比べたいのは「2 件目の業務（契約書レビュー）を作る追加工数」。同じ人が両方の arm を行うため、学習効果を避けられない。

## 選択肢
| 案 | 内容 | 学習効果の向き |
|---|---|---|
| A ベースラインを先に | 請求書の Factory 版（Phase 3）の後、契約書のベースラインを別リポジトリで作り、その後 Factory 版の契約書（Phase 4） | Factory に有利（2 回目のため）。報告で明記 |
| B Factory を先に | Phase 4 の後でベースライン | ベースラインに有利（業務を既に理解している） |
| C 別の人がベースライン | 学習効果が小さい | 人の技量差。人を確保できるか不明 |

## 決定
A を基本とし、学習効果は「Factory に有利な方向の偏り」として報告で必ず明記する。加えて、**両方の arm で同じ「要件変更」**（契約のポリシーに 1 条項追加、請求書に 1 項目追加）を最後に行い、変更対応の工数を比べる（こちらは順序の影響が小さい）。評価者を別にできるなら別にする（できなければ書く）。

## 条件
- ベースラインは別リポジトリ・別セッション（Codex）、Factory の Catalog・Composer・評価コード・Capability を使わない。
- 同じ凍結済みの要件・受入条件・dev データ・環境・モデル予算。ホールドアウトのラベルは両方に見せない。
- 事前登録の文書（`docs/experiment/preregistration.md`）を Codex が案を作り、人が承認してから実施。
