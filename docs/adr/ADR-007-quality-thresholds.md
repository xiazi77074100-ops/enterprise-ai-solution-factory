## 決定（合否の判定はホールドアウトで行う）

| 指標 | 閾値 | 種別 |
|---|---|---|
| 重大な誤りの黙認（重大項目・重大ルールの誤りが人の確認を経ずに `succeeded` になる） | 0 件 | 必須（1 件で不合格） |
| 重大ルールの再現率（`fail` または `uncertain` で確認へ回したものを検出とみなす） | 1.0 | 必須 |
| 根拠の位置の正しさ（照合済みの根拠のうち、正解のページ・範囲と重なる割合） | 0.9 以上 | 必須 |
| 照合できない根拠の扱い | 全件「未確認」と表示 | 必須 |
| 確認の記録の完全さ（確認者・時刻・修正前後の値） | 100% | 必須 |
| 項目抽出（正規化一致のマクロ平均） | 0.85 以上 | 目安（下回っても不合格にはしないが、報告で明記） |
| セキュリティ | 自己診断で高・中 0 件、SCA の高・重大 0 件、秘密の検出 0 件 | 必須（G4） |

## ホールドアウト
- 各業務 30〜50 件のうち 25〜30%（各業務 10 件以上）を層別で分ける。
- 正解ラベルはリポジトリの外に置き、ハッシュだけ記録（`easf-eval-integrity`）。
- 凍結の手順と manifest の書式は `docs/design/fixture_plan.md`（Codex の案を CC が統合）。

## 注意
件数が少ないため統計的に強い主張はしない。報告では件数・層・誤りの具体例を必ず載せる。
