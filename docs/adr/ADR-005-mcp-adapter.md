# ADR-005 MCP SDK とアダプタ契約の対応

| 項目 | 内容 |

## 状況
FR-11：少なくとも 1 つの実際の MCP ツール呼び出し。Capability の契約は通信方式に依存しない。外部の実サービスとの接続は許可がない限り行わない。

## 決定
- 公式の MCP Python SDK（MIT）を使う。
- EASF 内に **自作のローカル MCP サーバ**（stdio、固定のコマンドで起動）を 1 つ置き、EvidenceLocator を MCP ツールとしても提供する。Workflow のノードは `kind: mcp_tool` の Capability 版を指し、アダプタが MCP のプロトコルでツールを呼ぶ。
- これは「実際の MCP プロトコルでの呼び出し」であり、**外部の実連携ではない**。報告書・画面ではそのとおりに書く。
- 契約との対応：Capability の `input_schema` / `output_schema` ＝ MCP ツールの入力スキーマ / 構造化出力。登録時にサーバが広告するツールのスキーマと Catalog の契約を照合し、違えば登録を拒否する。
- MCP の Resource・Prompt は実行ノードにしない（v1 の `kind` から外す）。参照データが必要になったら別の ADR。
- 許可リスト：アダプタは Catalog に登録したツール名だけを呼ぶ。サーバが広告する他のツールは無視する。

## 影響
- MCP サーバのプロセスの起動・停止・タイムアウトをアダプタが管理する。
- 将来の外部 MCP サーバ（HTTP）は、ADR-002 と同じ接続先の許可リストと安全な HTTP クライアントを使う。
