## 状況
合成の請求書・契約書（PDF・PNG・JPEG）からページごとのテキストと文字の位置を取り出し、根拠（ページ・範囲・ハッシュ）に使う。スキャン画像は各業務 5 件程度（D-005）。

## 選択肢
| 観点 | テキスト層の抽出（pypdfium2 / pdfplumber） | PyMuPDF | Tesseract（jpn） | PaddleOCR | LLM の画像入力（ADR-002） | クラウドの文書解析 |
|---|---|---|---|---|---|---|
| ライセンス | Apache-2.0・BSD / MIT | **AGPL-3.0 または商用** | Apache-2.0 | Apache-2.0 | 提供元の規約 | 有料 |
| 日本語 | テキスト層があれば正確 | 同左 | 縦書き・小さい字に弱い | Tesseract より良いとされるが依存が大きい | 良いが非決定的・費用 | 良い |
| 位置情報 | あり | あり | あり | あり | 不確か | あり |
| 費用 | 0 | 0 | 0 | 0 | トークン課金 | 課金 |

## 決定
- 主：テキスト層の抽出（候補 pypdfium2 または pdfplumber。Phase 3 の着手時に日本語の合成 PDF で両方を試し、抽出の正確さと位置の取りやすさで 1 つに決める）。
- スキャン画像：Tesseract（jpn）を既定、精度が足りなければ LLM の画像入力を試す（実 API の承認後）。OCR の結果は「OCR 由来」と印を付け、根拠は位置の照合ができなければ「未確認」。
- PyMuPDF は AGPL のため採用しない。

## 影響
- DocumentParser の出力に `extraction_method`（`text_layer` / `ocr_tesseract` / `ocr_llm`）とページごとの信頼度（取れる場合）を持たせる。
- 解析は別プロセスで時間とメモリに上限（`jp-secure-coding` upload-and-files.md）。
- Tesseract を使う場合、コンテナに日本語の学習データを入れる（ライセンスは Apache-2.0）。
